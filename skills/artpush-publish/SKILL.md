# Публикации картин из ArtPush

## Назначение

Подготовка публикации картины на площадках: готовность, предпросмотр (тексты и файлы под требования
площадки), выгрузка, пакет для ручного размещения, отметка ссылки, журнал, аккаунты и профили.
Способ выгрузки у каждой цели виден в предпросмотре (`method`). В канал Telegram с подключённым и проверенным
ботом система публикует сама (`api`). Instagram с принятым ключом система тоже публикует сама. VK с фото
система сейчас не отправляет даже с принятым ключом: предпросмотр предлагает пакет (см. раздел VK).
Остальные цели (Telegram без бота, цели без ключа) уходят пакетом (ZIP), который размещает человек. Общие правила, коды выхода и ключ описаны в скилле `artpush`.

## Правила

1. **Выгрузка только после «да» человека.** Сначала `publish preview`. Покажи человеку, что и куда уйдёт:
   цели, файлы, подпись, цену. Спроси «Выгрузить? (да / нет)». После явного «да» выполни
   `publish run <снимок> --yes`. Молчание, «наверное» и «сам реши» — это не «да». Пакет через
   `publish package` тоже публичен по сути: перед ним покажи предпросмотр и спроси.
2. **Неоднозначную цель уточни.** «Опубликуй в Telegram» при двух каналах: спроси, какой взять (ru, en или
   оба), и не бери все. Утилита сама отвечает кодом 1 `target_ambiguous` и списком меток в `choices`.
3. **Заметки, теги и метки в публикацию не попадают никогда.** Текст собирает система из карточки по
   шаблону. Свою подпись для одной публикации передай через `--caption-file`, карточка от этого не меняется.
4. **Карточка изменилась после предпросмотра** (код 2, «Карточка изменилась — повторите publish preview»):
   сделай `publish preview` заново и снова покажи и спроси. Старый снимок не годится.
5. **Повтор в тот же аккаунт** (код 2, `already_placed`): спроси человека. `--force` добавляй только после
   его «да». Размещение в другом аккаунте той же площадки (Instagram ru и Instagram en) не мешает: это справка.
6. **Ключи и ссылки вводит только человек.** Ключ бота (от @BotFather) и ссылку VLESS агент не видит, не
   просит прислать в диалоге и не передаёт ни в аргументах, ни в файлах, которые создал сам. Агент
   запускает `publish bot secret set <бот>` (или `admin egress set-link`) и просит человека ввести значение
   в терминале (ввод скрыт) или указать свой файл через `--from-file`. Без терминала и без файла команда
   откажет кодом `secret_needs_tty`: это нормально, не обходи. Ответ покажет только номер бота и `@username`.
7. **Выгрузка через API необратима для площадки.** Пост в канале увидят подписчики. Поэтому «да» нужно на
   показ того, что и в какой канал уйдёт (в `publish run` это строка «система сама опубликует в канал»).
   Не повторяй `publish run` с `--force` и не ставь `publish retry --yes` без «да» человека (без `--yes`
   команда сама спросит человека в терминале).
8. **«Не подтверждено» (`unconfirmed`)**: обрыв связи после отправки, неизвестно, дошёл ли пост. Агент **сам
   не повторяет** отправку: двойной пост в канале хуже задержки. Сообщи человеку ошибку и попроси проверить
   канал. Дальше по ответу человека: `publish resolve <публикация> --arrived <ссылка>` (пост дошёл) или
   `publish resolve <публикация> --retry` (не дошёл), оба с `--yes` только после его «да».
9. **Нет права на публикацию** (`no_right`, например картина ученика без согласия): заполнением полей это не
   исправить, и `--force` не поможет. Скажи об этом человеку.

## Цели

`--target` принимает `площадка:метка` (`telegram:ru`, `tg:en`, `instagram:en`, `vk:мс`) или номер аккаунта
(`12`). Площадка без метки (`--target instagram`) годится, когда аккаунт на ней один. Назначение указывается
третьей частью или после номера: `tg:ru:post`, `12:vk.wall`. Список аккаунтов и меток:

```sh
artpush publish accounts --table
```

## Подготовить и выложить картину

```sh
artpush publish readiness 12 --target instagram:en --target telegram:ru --table
artpush publish preview 12 --target instagram:en --target telegram:ru
artpush publish run 3f9a01bc --yes          # только после «да» человека
artpush publish package --publication 31 --to ~/Загрузки
artpush publish placed 31 --url https://t.me/kmikhailov_art/412
```

- `--url` в `publish mark` и `publish placed` — ссылка на пост. Адрес системы этим командам передаётся
  только до имени команды: `artpush --url=https://… publish mark 12 --target tg:ru --url https://t.me/…`.
- `publish preview` готовит файлы под площадку (это правка, ключ `write`) и ждёт подготовки до 120 с.
  Печатает тексты, файлы (`tiles`: подготовлен или как есть, размеры, объём) и **номер снимка** из 8 знаков.
  Утилита запоминает тело предпросмотра под этим номером. Снимки старше 14 дней удаляются сами.
- Свои файлы и порядок: `--media 3,1,2`. Своя подпись: `--caption-file подпись.txt`. Свой alt: `--alt "…"`.
  Свой выбор не меняет ни карточку, ни метки файлов.
- `publish run <снимок>` показывает в stderr, что и куда уйдёт, и без `--yes` спрашивает человека в
  терминале. Запуск создаёт публикации «ждёт размещения» и пакеты. Скачай их через
  `publish package --publication <номер>`, а когда человек разместит и пришлёт ссылку, отметь её через
  `publish placed <номер> --url …`.
- Пакет без запуска (журнал не пишет):

  ```sh
  artpush publish package --snapshot 3f9a01bc --to ~/Загрузки
  artpush publish package 12 --target instagram:en --target telegram:ru --snapshot 3f9a01bc --out ~/Загрузки
  artpush publish package 12 --target telegram:ru -o пакет.zip
  ```

  С `--snapshot` пакеты собираются ровно по показанному предпросмотру (свои файлы и подпись из него).
  `--target` рядом выбирает часть целей снимка: если цели в снимке нет, будет ошибка `target_not_found`.
  `--out` — то же, что `--to`.

  ZIP содержит `текст.txt`, файлы `01.jpg…` и `чеклист.md`. Имя файла даёт система. Человек разместил
  пакет, скачанный без запуска, и прислал ссылку: отметь её через
  `publish mark 12 --target telegram:ru --url https://…`, источник будет «отмечено вручную».
  Для работ, размещённых задним числом, добавь `--date 2026-09-03`.

Пример диалога:

> Вы › подготовь картину №12 к публикации в Instagram en и Telegram
>
> `artpush publish readiness 12 --target instagram:en --target telegram:ru --target telegram:en --table`
>
> Агент › У Telegram два канала, оба готовы: ru и en. Какой взять — ru, en или оба?
>
> Вы › только ru
>
> `artpush publish preview 12 --target instagram:en --target telegram:ru`
>
> Агент › Instagram en — карусель из 3 фото в 4:5, у 2-го и 3-го белые поля, подпись на английском без цены.
> Telegram ru — альбом из 3 фото, подпись с ценой, описание вторым сообщением. Собрать пакеты?
>
> Вы › да
>
> `artpush publish package --snapshot 3f9a01bc --to ~/Загрузки`
>
> Агент › Пакеты в «Загрузках», в каждом чеклист. Когда разместите, пришлите ссылки, и я отмечу размещение.

## Что можно опубликовать

```sh
artpush publish candidates --table                  # готовы хотя бы для одного аккаунта, где их ещё нет
artpush publish candidates --not-ready --table      # неготовые с короткой причиной
artpush publish candidates --catalog "Пейзажи" --table
artpush publish readiness --catalog "Пейзажи" --target vk:мс   # каталог с вложенными, причины по картинам
```

`publish readiness <№…>` (ключ read) по каждой цели показывает: готова или нет, все причины
(блокирующие — «причина», остальные — «предупреждение» или «справка»), значок размещения в этом аккаунте и
способ выгрузки (`api` — система сама, `package` — пакет, с причиной). `--table` печатает вид для человека, без него
выдаётся JSON (`where` — готовая цель для `--target`). Без `--target` проверяются все аккаунты.

## Журнал и размещения картины

```sh
artpush publish log --painting 12 --table
artpush publish log --account tg:ru --state failed --since 2026-10-01 --table
artpush painting placements 12 --table   # значки по аккаунтам; без --table — ещё и журнал картины
```

Признак «устарела» означает, что после публикации менялись поля текста или цены. Система пост на площадке
не трогает: обновить его можно только вручную.

## Метки площадок у файлов

Файл с меткой площадки (`telegram`, `instagram`, своя метка аккаунта) попадает в отбор файлов для этой цели.

```sh
artpush media list 12 --table                    # столбец labels
artpush media list 12 --label instagram --table  # только файлы с меткой
artpush media label 502 --remove instagram       # больше не брать файл в Instagram
artpush media label 502 --add instagram
artpush publish labels apply instagram.post      # проставить по архиву: сначала сколько файлов
artpush publish labels apply tg:ru --yes         # после «да» человека
```

`labels apply` работает на аккаунт целиком (все его назначения) или на одно назначение. Сочетание
`12:vk.wall` утилита отклоняет: укажи `12` или `vk.wall`.

Снятую человеком метку система сама не возвращает: ни импорт, ни перенос, ни проставление по архиву.
Площадка без неархивного аккаунта меток файлам не ставит; заведя первый аккаунт площадки, предложи человеку
`publish labels apply` по её назначению.

## Аккаунты и профили

```sh
artpush publish account show 3
artpush publish account create --platform telegram --title "Канал en" --language en --currency EUR --label en
artpush publish account set 3 --template-file telegram.post шаблон.txt --pace-minutes 5
artpush publish account archive 3
artpush publish account delete 3 --yes        # после «да»; аккаунт с публикациями — только в архив
artpush publish profiles --table
artpush publish profile set instagram.post --json профиль.json   # покажет, кто станет (не)готов, спросит
artpush publish profile reset instagram.post
```

- Метку аккаунта (до 3 знаков) без `--label` предложит система. Тестовым свой аккаунт делает сама
  художница (`--test`): тестовые аккаунты и выгрузки в них в статистику не входят.
- `profile set` и `profile reset` сначала печатают в stderr, сколько картин станут готовыми и сколько
  перестанут. Затем без `--yes` спрашивают. Покажи это человеку и выполни с `--yes` только после «да».

## Боты Telegram и выгрузка через API

Бот Telegram заводит и подключает человек или агент по его просьбе; ключ бота вводит только человек.

```sh
artpush publish bot list --table
artpush publish bot create --title "ArtPush"
artpush publish bot secret set 4                  # человек вводит ключ в терминале; или --from-file ключ.txt
artpush publish bot secret check 4 --wait         # до 60 с; нет итога: «worker недоступен?»
artpush publish account set tg:ru --bot 4         # канал публикуется этим ботом; --no-bot снимает
artpush publish account check tg:ru --wait        # права бота в канале (администратор с правом публикации)
artpush publish bot secret delete 4 --yes         # после «да»: каналы бота переходят на пакет
artpush publish bot delete 4 --yes                # бот с каналами не удаляется
```

- В `bot secret set` ключа в аргументах нет, это сделано намеренно. Не пытайся передать его в команде.
- После проверки смотри `state` бота и `cred_state` аккаунта: `ok`, `rejected` (ключ не принят или бот
  не администратор), `unreachable` (нет связи; смотри выход к площадкам).
- Способ цели берётся из предпросмотра. `publish preview` запоминает `method` в снимке, `publish run`
  отправляет его обратно: если способ изменился (ключ стёрт, выход отключён), будет код 2 `method_changed`,
  повтори `publish preview` и покажи человеку новый план.

## VK

Ключ сообщества VK система проверяет и хранит, но запись с фото от имени сообщества VK не принимает. Поэтому
публикация в VK с фото не отправляется: предпросмотр ставит `method: package` с причиной, а выгрузка отвечает
`vk_photos_unsupported` («VK не прикрепляет фото к записи от имени сообщества, поэтому запись не отправлена.
Публикация в VK с фото появится, когда будет подключён вход через пользователя VK.»). Предложи человеку пакет
(`publish package`) и отметку ссылки после ручного размещения. Вход через пользователя VK (VK ID) запланирован.
Ключ вводит только человек: агент значения не видит и не просит прислать его в диалог.

```sh
artpush publish account secret set 8              # человек вводит ключ в терминале; или --from-file ключ.txt
artpush publish account check 8 --wait            # до 60 с; печатает состояние сообщества словами
artpush publish account secret delete 8 --yes     # после «да»: ключ удалён, проверки сообщества нет
```

- В `account secret set` ключа в аргументах нет, это сделано намеренно. На аккаунте Telegram команда ответит
  `secret_on_bot`: у Telegram ключ у бота, нужен `publish bot secret set`.
- `cred_state` после проверки: `ok`, `rejected` (ключ не принят), `no_rights` (у ключа нет прав), `not_found`
  (сообщество не найдено: проверь поле «Сообщество»), `no_messages`, `wrong_group`, `closed`, `down` (VK не
  отвечает), `no_egress`, `no_key`.
- `no_messages` («сообщения выключены»): в сообществе выключены сообщения или у ключа нет права «Сообщения
  сообщества». Объясни человеку оба шага: включить сообщения сообщества (Управление, Сообщения) и отметить право
  у ключа. Сам проверку не повторяй, пока он не скажет, что исправил.
- `wrong_group` («чужой ключ»): ключ выдан другому сообществу, его название и номер — в `cred_error`. Попроси
  человека создать ключ в настройках этого сообщества и записать его заново.
- Капча или `closed` («VK закрыл путь»): предложи человеку пакет (`publish package`) для ручного размещения.

## Instagram

Аккаунт Instagram публикует сам по долгому ключу профиля («Автор» или «Бизнес»; личный профиль не подходит).
Ключ человек создаёт в Meta (Generate token) и вводит сам: агент значения не видит и не просит прислать его в диалог.
Команды те же, что у VK:

```sh
artpush publish account secret set 14             # скрытый ввод в терминале; без терминала команда откажет
artpush publish account check 14 --wait          # печатает @имя, состояние и срок ключа
artpush publish account secret delete 14 --yes   # после «да»: выгрузка перейдёт на пакет
```

- Строку, не похожую на ключ Instagram, сервер отклонит кодом `bad_token`: попроси человека вставить ключ заново.
- `cred_state` после проверки: `ok` (работает; срок в `token_expires_at`, последнее продление в `token_refreshed_at`),
  `wrong_account` (ключ выдан другому профилю: нужен ключ именно этого профиля), `personal` (личный профиль:
  переключить на «Автор» или «Бизнес» в приложении Instagram), `expired` (ключ истёк: записать новый), `rejected`
  (Instagram не принял ключ: записать новый), `not_found` (не указан профиль: заполнить поле аккаунта), `no_rights`
  (у ключа нет права публиковать: создать ключ с ним), `no_egress` (нет выхода к Instagram: настройка у
  администратора), `down` (Instagram не отвечает: повторить позже), `no_key`. Проверка печатает также тип профиля
  («Автор», «Бизнес») и квоту «сегодня N из 100». Сам проверку не повторяй, пока человек не скажет, что исправил.
- Без принятого ключа цель Instagram уходит пакетом (`publish package`) для ручного размещения; в
  `publish accounts --table` столбец «upload» показывает «пакет (нет ключа)» или «ключом Instagram».
- Система продлевает ключ сама (раз в сутки, если прошло больше 7 дней). За 7 дней до истечения без продления
  человеку нужен новый ключ.
- Instagram забирает фото по временной публичной ссылке на ArtPush (живёт час, отдаёт только файлы этой
  публикации). Если Instagram не смог их скачать, смотри выход к площадкам и `publish log`.
- Дневной предел публикаций Instagram (100 в сутки): при исчерпании публикация ждёт, а не падает. Скажи человеку
  время, не жди часами: Ctrl-C перестаёт ждать, отправка идёт дальше.
- Публичный пост через систему не удалить. Перед `publish run` покажи, что и в какой профиль уйдёт.
- `publish run --wait` печатает шаги отправки: «Instagram забирает фото 2 из 6», «Instagram обрабатывает
  публикацию», «публикуем». «Не подтверждено» система сначала сверяет сама; если осталось, разбери его через
  `publish resolve` (раздел ниже).

## Запуск, ожидание и разбор

```sh
artpush publish run 3f9a01bc --yes --wait         # после «да»; ждёт отправки, печатает ссылки на посты
artpush publish cancel 31                         # снять из очереди (пока не ушла)
artpush publish retry 31 --yes                    # после failed, если снимок совпадает; только после «да»
artpush publish send-description 31               # описание, не ушедшее вторым сообщением
artpush publish resolve 31 --arrived https://t.me/artpush/412 --yes
artpush publish resolve 31 --retry --yes
```

- Публикации идут по очереди с темпом аккаунта, поэтому `--wait` может занять минуты. Ctrl-C перестаёт
  ждать, но отправка идёт дальше: состояние покажет `publish log`.
- Код выхода `publish run --wait` 1 означает `failed` или `unconfirmed` у какой-то публикации. Ссылки и
  причины в stderr, полный ответ в stdout.

## Выход к площадкам и ключ шифрования (администратор)

```sh
artpush admin egress --table                      # ссылка только в виде «сервер, порт, имя профиля»
artpush admin egress --check --wait               # проверка площадок, до 60 с
artpush admin egress set-link                     # человек вводит ссылку VLESS в терминале (или --from-file)
artpush admin egress route telegram vless --yes   # через VLESS или direct (напрямую); после «да»
artpush admin egress delete-link --yes
artpush admin secrets                             # состояние ключа шифрования и подписи записей
artpush admin secrets --confirm-copy              # человек подтверждает, что копия ключа сохранена
```

Нужен ключ `admin` администратора. Значений секретов система не отдаёт никому. `route … vless` без ссылки
даёт 409 `no_link`. Если площадка отмечена «через VLESS», а выход не работает, прямой отправки нет:
публикация упадёт с `egress_down`, а не уйдёт в обход.

`state` у `admin secrets`: `ok`; `missing` — нет файла ключа (или каталог ключа не смонтирован);
`mismatch` — ключ не подходит к секретам; `unreadable` — нет доступа к файлу ключа. Кроме `ok` выгрузка через API
и VLESS выключены, пакеты работают. Запись секрета тогда даёт 409 `key_unusable` с причиной. Скажи
администратору: чинит он на сервере, не агент.

## Ошибки

- Код 3 `scope_denied` на `publish preview`, `run`, `mark` или `placed`: ключ только для чтения. С ним доступны
  `publish readiness`, `publish candidates`, `publish package` и `publish log`. Для подготовки нужен ключ
  `write`, скажи об этом человеку.
- `secret_needs_tty` (код 1): секрет можно ввести только в терминале или из файла. Попроси человека.
- `check_timeout` (код 1): проверка не завершилась за 60 с, вероятно не работает worker. Скажи человеку.
- Код 2 `method_changed`: способ цели изменился после предпросмотра. Повтори `publish preview`.
- Код 3 `not_confirmed`: человек не подтвердил, ничего не сделано.
- 409 `publication_pending` на `publish mark`: публикация в этот аккаунт ещё отправляется или ждёт разбора
  «не подтверждено». Отметку вручную не делай. Дождись итога или разбери её (`publish resolve`).
- `snapshot_not_found` (код 1): снимок с другой системы или утилита его не помнит. Повтори `publish preview`.
- `timeout` (код 1): файлы ещё готовятся. Подожди и повтори `publish preview`.
- `preparing` (код 2) при запуске означает то же: повтори `publish preview`.
- `not_prepared` (код 2) на `publish package`: файлы под цель ещё ни разу не готовили. Нужен `publish preview`
  ключом `write`; с ключом только для чтения скажи об этом человеку.
