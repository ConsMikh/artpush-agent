# Публикации картин из ArtPush

## Назначение

Подготовка публикации картины на площадках: готовность, предпросмотр (тексты и файлы под требования
площадки), пакет для ручного размещения, отметка ссылки, журнал выгрузок, аккаунты и профили. Сейчас система
сама на площадки не выкладывает: и запуск, и «Скачать пакет» дают ZIP, который размещает человек.
Учётных данных и ботов площадок у агента нет. Общие правила, коды выхода и ключ описаны в скилле `artpush`.

## Правила

1. **Выгрузка только после «да» человека.** Сначала `publish preview`. Покажи человеку, что и куда уйдёт:
   цели, файлы, подпись, цену. Спроси «Выгрузить? (да / нет)». После явного «да» выполни
   `publish run <снимок> --yes`. Молчание, «наверное» и «сам реши» — это не «да». Пакет через
   `publish package` тоже публичен по сути: перед ним покажи предпросмотр и спроси.
2. **Неоднозначную цель уточни.** «Опубликуй в Telegram» при двух каналах: спроси, какой взять (ru, en или
   оба), и не бери все. Утилита сама отвечает кодом 1 `target_ambiguous` и списком меток в `choices`.
3. **Заметки, теги и метки в публикацию не попадают никогда.** Текст собирает система из карточки по
   шаблону. Свою подпись для одной публикации передай через `--caption-file`, карточка от этого не меняется.
4. **Карточка изменилась после предпросмотра** (код 2, «Карточка изменилась — повторите publish preview»):
   сделай `publish preview` заново и снова покажи и спроси. Старый снимок не годится.
5. **Повтор в тот же аккаунт** (код 2, `already_placed`): спроси человека. `--force` добавляй только после
   его «да». Размещение в другом аккаунте той же площадки (Instagram ru и Instagram en) не мешает: это справка.
6. **Нет права на публикацию** (`no_right`, например картина ученика без согласия): заполнением полей это не
   исправить, и `--force` не поможет. Скажи об этом человеку.

## Цели

`--target` принимает `площадка:метка` (`telegram:ru`, `tg:en`, `instagram:en`, `vk:мс`) или номер аккаунта
(`12`). Площадка без метки (`--target instagram`) годится, когда аккаунт на ней один. Назначение указывается
третьей частью или после номера: `tg:ru:post`, `12:vk.wall`. Список аккаунтов и меток:

```sh
artpush publish accounts --table
```

## Подготовить и выложить картину

```sh
artpush publish readiness 12 --target instagram:en --target telegram:ru --table
artpush publish preview 12 --target instagram:en --target telegram:ru
artpush publish run 3f9a01bc --yes          # только после «да» человека
artpush publish package --publication 31 --to ~/Загрузки
artpush publish placed 31 --url https://t.me/kmikhailov_art/412
```

- `--url` в `publish mark` и `publish placed` — ссылка на пост. Адрес системы этим командам передаётся
  только до имени команды: `artpush --url=https://… publish mark 12 --target tg:ru --url https://t.me/…`.
- `publish preview` готовит файлы под площадку (это правка, ключ `write`) и ждёт подготовки до 120 с.
  Печатает тексты, файлы (`tiles`: подготовлен или как есть, размеры, объём) и **номер снимка** из 8 знаков.
  Утилита запоминает тело предпросмотра под этим номером. Снимки старше 14 дней удаляются сами.
- Свои файлы и порядок: `--media 3,1,2`. Своя подпись: `--caption-file подпись.txt`. Свой alt: `--alt "…"`.
  Свой выбор не меняет ни карточку, ни метки файлов.
- `publish run <снимок>` показывает в stderr, что и куда уйдёт, и без `--yes` спрашивает человека в
  терминале. Запуск создаёт публикации «ждёт размещения» и пакеты. Скачай их через
  `publish package --publication <номер>`, а когда человек разместит и пришлёт ссылку, отметь её через
  `publish placed <номер> --url …`.
- Пакет без запуска (журнал не пишет):

  ```sh
  artpush publish package --snapshot 3f9a01bc --to ~/Загрузки
  artpush publish package 12 --target instagram:en --target telegram:ru --snapshot 3f9a01bc --out ~/Загрузки
  artpush publish package 12 --target telegram:ru -o пакет.zip
  ```

  С `--snapshot` пакеты собираются ровно по показанному предпросмотру (свои файлы и подпись из него).
  `--target` рядом выбирает часть целей снимка: если цели в снимке нет, будет ошибка `target_not_found`.
  `--out` — то же, что `--to`.

  ZIP содержит `текст.txt`, файлы `01.jpg…` и `чеклист.md`. Имя файла даёт система. Человек разместил
  пакет, скачанный без запуска, и прислал ссылку: отметь её через
  `publish mark 12 --target telegram:ru --url https://…`, источник будет «отмечено вручную».
  Для работ, размещённых задним числом, добавь `--date 2026-09-03`.

Пример диалога:

> Вы › подготовь картину №12 к публикации в Instagram en и Telegram
>
> `artpush publish readiness 12 --target instagram:en --target telegram:ru --target telegram:en --table`
>
> Агент › У Telegram два канала, оба готовы: ru и en. Какой взять — ru, en или оба?
>
> Вы › только ru
>
> `artpush publish preview 12 --target instagram:en --target telegram:ru`
>
> Агент › Instagram en — карусель из 3 фото в 4:5, у 2-го и 3-го белые поля, подпись на английском без цены.
> Telegram ru — альбом из 3 фото, подпись с ценой, описание вторым сообщением. Собрать пакеты?
>
> Вы › да
>
> `artpush publish package --snapshot 3f9a01bc --to ~/Загрузки`
>
> Агент › Пакеты в «Загрузках», в каждом чеклист. Когда разместите, пришлите ссылки, и я отмечу размещение.

## Что можно опубликовать

```sh
artpush publish candidates --table                  # готовы хотя бы для одного аккаунта, где их ещё нет
artpush publish candidates --not-ready --table      # неготовые с короткой причиной
artpush publish candidates --catalog "Пейзажи" --table
artpush publish readiness --catalog "Пейзажи" --target vk:мс   # каталог с вложенными, причины по картинам
```

`publish readiness <№…>` (ключ read) по каждой цели показывает: готова или нет, все причины
(блокирующие — «причина», остальные — «предупреждение» или «справка»), значок размещения в этом аккаунте и
способ выгрузки («пакет — учётных данных площадок пока нет»). `--table` печатает вид для человека, без него
выдаётся JSON (`where` — готовая цель для `--target`). Без `--target` проверяются все аккаунты.

## Журнал и размещения картины

```sh
artpush publish log --painting 12 --table
artpush publish log --account tg:ru --state failed --since 2026-10-01 --table
artpush painting placements 12 --table   # значки по аккаунтам; без --table — ещё и журнал картины
```

Признак «устарела» означает, что после публикации менялись поля текста или цены. Система пост на площадке
не трогает: обновить его можно только вручную.

## Метки площадок у файлов

Файл с меткой площадки (`telegram`, `instagram`, своя метка аккаунта) попадает в отбор файлов для этой цели.

```sh
artpush media list 12 --table                    # столбец labels
artpush media list 12 --label instagram --table  # только файлы с меткой
artpush media label 502 --remove instagram       # больше не брать файл в Instagram
artpush media label 502 --add instagram
artpush publish labels apply instagram.post      # проставить по архиву: сначала сколько файлов
artpush publish labels apply tg:ru --yes         # после «да» человека
```

`labels apply` работает на аккаунт целиком (все его назначения) или на одно назначение. Сочетание
`12:vk.wall` утилита отклоняет: укажи `12` или `vk.wall`.

Снятую человеком метку система сама не возвращает: ни импорт, ни перенос, ни проставление по архиву.
Площадка без неархивного аккаунта меток файлам не ставит; заведя первый аккаунт площадки, предложи человеку
`publish labels apply` по её назначению.

## Аккаунты и профили

```sh
artpush publish account show 3
artpush publish account create --platform telegram --title "Канал en" --language en --currency EUR --label en
artpush publish account set 3 --template-file telegram.post шаблон.txt --pace-minutes 5
artpush publish account archive 3
artpush publish account delete 3 --yes        # после «да»; аккаунт с публикациями — только в архив
artpush publish profiles --table
artpush publish profile set instagram.post --json профиль.json   # покажет, кто станет (не)готов, спросит
artpush publish profile reset instagram.post
```

- Метку аккаунта (до 3 знаков) без `--label` предложит система. Тестовым аккаунт делает только
  администратор (`--test`).
- `profile set` и `profile reset` сначала печатают в stderr, сколько картин станут готовыми и сколько
  перестанут. Затем без `--yes` спрашивают. Покажи это человеку и выполни с `--yes` только после «да».

## Ошибки

- Код 3 `scope_denied` на `publish preview`, `run`, `mark` или `placed`: ключ только для чтения. С ним доступны
  `publish readiness`, `publish candidates`, `publish package` и `publish log`. Для подготовки нужен ключ
  `write`, скажи об этом человеку.
- Код 3 `not_confirmed`: человек не подтвердил, ничего не сделано.
- `snapshot_not_found` (код 1): снимок с другой системы или утилита его не помнит. Повтори `publish preview`.
- `timeout` (код 1): файлы ещё готовятся. Подожди и повтори `publish preview`.
- `preparing` (код 2) при запуске означает то же: повтори `publish preview`.
- `not_prepared` (код 2) на `publish package`: файлы под цель ещё ни разу не готовили. Нужен `publish preview`
  ключом `write`; с ключом только для чтения скажи об этом человеку.
