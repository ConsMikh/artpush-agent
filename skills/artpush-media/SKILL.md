# Фото и видео картины в ArtPush

## Назначение

Медиафайлы одной картины: загрузка, скачивание, порядок, главное, перенос между картинами, обработка
(формат, размер, объём) и карточка файла (метки, заметка, имя, версии).
Общие правила, коды выхода и ключ — в скилле `artpush`. Много фото, которые ещё не разложены по картинам, —
это импорт папки (`artpush-import`), а не загрузка по одному.

## Посмотреть файлы

```sh
artpush media list 184 --table        # номер медиа, имя, тип, главное ли
```

## Загрузка и скачивание

```sh
artpush media upload 184 ~/фото/закат-1.jpg ~/фото/закат-2.jpg
artpush media download 184 --all --to ~/Загрузки/184
artpush media download 184 --main --to ~/Загрузки/184            # только главное фото
artpush media download 184 --main --thumbnail --to /tmp/превью   # его миниатюра
artpush media download 184 --media 11 --thumbnail --to /tmp/превью
```

- Файлы грузятся по одному, сбой сети и 5xx утилита повторяет сама. Темп загрузок — 60 в минуту на ключ;
  при 429 утилита ждёт сама.
- Сервер может отклонить файл (дубль, неподдерживаемый формат) — причина в выводе; перескажи человеку.
- Скачивание не перезаписывает файлы в папке: занятое имя получает номер медиа впереди.

## Показать фото человеку

Адреса в карточке относительные и требуют ключ — сам по ним человек картинку не увидит. Скачай миниатюры
и покажи файлы:

```sh
artpush paintings thumbs 101,118,184 --to /tmp/превью     # <номер картины>.jpg, главное фото каждой
artpush media download 184 --all --thumbnail --to /tmp/превью   # все фото одной картины
```

Миниатюры для показа каждый раз скачивай заново, в новую папку (или поверх): ранее скачанные файлы не
переиспользуй — главное фото могло смениться, особенно после «Порядок и главное фото».

Claude Code — прочитай файлы как изображения или собери страницу со встроенными (base64) картинками;
Codex — покажи локальные файлы так, как умеет клиент. Папка временная.

## Порядок и главное фото

```sh
artpush media order 184 12,11,13      # полный новый порядок номеров медиа
artpush media main 184 12
```

Без подтверждения: это обратимо и делается по прямой просьбе.

## Перенос в другую картину — только с подтверждением

```sh
artpush media transfer --ids 12,13 --to 187 --preview --table
artpush media transfer --ids 12,13 --new --catalog 5 --preview --table   # в новую картину
# показать человеку план: какие файлы, откуда, куда; спросить «Перенести? (да / нет)»
artpush media transfer --ids 12,13 --to 187 --apply pv_…
```

- `--apply` — с теми же `--ids` и `--to`/`--new`, что в preview, и только после явного «да».
- Жетон одноразовый, 10 минут; после ошибки — новый `--preview` и новый вопрос.

## Файлы по требованиям

Поручение вида «подготовь файлы к заявке, вот приглашение». Обработка создаёт новые файлы рядом с
исходными; исходные не меняются.

1. Прочитай текст приглашения целиком.
2. Выпиши требования таблицей: формат, размер (px или см), dpi, объём, цветовой профиль, имя файла.
   Неясное или противоречивое не додумывай — спроси человека.
3. Сопоставь требования с флагами `media edit`:

   | Требование | Флаг |
   |---|---|
   | формат JPEG / PNG / TIFF / WebP | `--format jpeg` |
   | длинная сторона 2000 px | `--long-side 2000` |
   | ровно 1920×1080 px | `--size-px 1920x1080` (`--fit pad` — поля, `--fit crop` — обрезать) |
   | 30×40 см, 300 dpi | `--size-cm 30x40 --dpi 300` |
   | не больше 2 МБ | `--max-mb 2` (1 МБ = 1024×1024 байт, как в браузере) |
   | качество JPEG | `--quality 85` |
   | для печати / для экрана | `--profile print` / `--profile screen` |
   | имя «Фамилия_Название» | `--name "Петрова_{name}"` (`{name}` — имя исходного без расширения) |

4. Найди номера файлов (`artpush media list 184 --table`) и получи отчёт без сохранения:

   ```sh
   artpush media edit 31,45 --format jpeg --long-side 2000 --max-mb 2 --name "{name}-заявка" --label Выставка --dry-run
   ```

   В stderr — строки «файл — картина — итог px/см/dpi — формат/качество — объём → имя — предупреждения»,
   в JSON — `plan`. При `--max-mb` объём точный (проба сжатия), иначе — оценка «≈». Ключу только для
   чтения проба недоступна: объём будет оценкой, об этом скажет предупреждение.
5. Покажи человеку перечень «картина — файл — итоговые параметры — имя» и отметь, что не выполняется.
   Спроси «Сохранить? (да / нет)».
6. Только после явного «да» повтори ту же команду без `--dry-run`, с `--yes` и `--to` — забрать результаты:

   ```sh
   artpush media edit 31,45 --format jpeg --long-side 2000 --max-mb 2 --name "{name}-заявка" --label Выставка --yes --to ~/Заявка
   ```

- `--replace` (заменить содержимое, прежнее станет версией) — только по прямому поручению человека.
- Увеличение сверх исходного (`upscale_needed`) и объём больше предела (`unmet`) утилита не пропустит без
  флага: в `plan[].blocked` сказано, какого. Если хоть один файл требует решения, ничего не делается ни с
  одним файлом (код 3, «Ничего не изменено») — реши с человеком или убери этот файл из списка. Покажи человеку отчёт с предупреждением. Только если он
  согласился, повтори с `--allow-upscale` или `--accept-unmet` и передай его ответ в stdin:
  `echo да | artpush media edit 31 --max-mb 1 --accept-unmet --yes`. `--yes` эти два случая не снимает.
  Никогда не подставляй «да» сам — только дословный ответ человека.
- Итог — `done` и `failed` с причиной; сбой одного файла не останавливает остальные. Перескажи человеку
  `summary`.
- `thumbs_pending` в причине: миниатюры ещё готовятся — повтори через минуту.
- `timeout`: задание продолжает идти на сервере. Не повторяй вслепую — сначала проверь файлы картины
  (`artpush media list 184 --table`), а после `--replace` — версии (`artpush media versions 31 --table`):
  если результат уже есть, повтор создаст второй файл или вторую замену.

## Карточка файла: метки, заметка, имя, версии

```sh
artpush media label 31 --add Выставка        # --remove Выставка — убрать
artpush media note 31 "Отправлено в галерею"  # пустая строка — убрать заметку
artpush media rename 31 Закат-2026           # расширение остаётся прежним
artpush media versions 31 --table           # прежние версии после замен
artpush media restore 31 5 --yes            # вернуть версию 5 — только после «да» человека
```

`media restore` с `--yes` — только после явного «да» человека на вопрос «Вернуть версию 5?». Никогда не
подставляй «да» сам — только дословный ответ человека.

Метки и заметки видны только в архиве и в выдаваемые файлы не попадают. Окончательно удалить версию
агент не может — предложи человеку сделать это в браузере (карточка файла → «Версии»).

## Ошибки

- `preview_required` (код 2): вызвал перенос без `--preview`/`--apply` — начни с `--preview`.
- Код 2 с `conflict`: картину изменили параллельно — покажи человеку и спроси.
- Код 3: ключ только для чтения или чужая картина — остановись и скажи человеку.
- Код 3 и «Ничего не изменено» у `media edit` / `media restore`: человек не подтвердил или нужен флаг
  решения — ничего не записано; покажи план и спроси.
