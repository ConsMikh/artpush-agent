# Фото и видео картины в ArtPush

## Назначение

Медиафайлы одной картины: загрузка, скачивание, порядок, главное, перенос между картинами, обработка
(формат, размер, объём, выравнивание, тон, поля, подпись, сведения в файле) и карточка файла (метки, заметка, имя, версии).
Общие правила, коды выхода и ключ — в скилле `artpush`. Много фото, которые ещё не разложены по картинам, —
это импорт папки (`artpush-import`), а не загрузка по одному.

## Посмотреть файлы

```sh
artpush media list 184 --table        # номер медиа, имя, тип, главное ли
```

## Загрузка и скачивание

```sh
artpush media upload 184 ~/фото/закат-1.jpg ~/фото/закат-2.jpg
artpush media download 184 --all --to ~/Загрузки/184
artpush media download 184 --main --to ~/Загрузки/184            # только главное фото
artpush media download 184 --main --thumbnail --to /tmp/превью   # его миниатюра
artpush media download 184 --media 11 --thumbnail --to /tmp/превью
```

- Файлы грузятся по одному, сбой сети и 5xx утилита повторяет сама. Темп загрузок — 60 в минуту на ключ;
  при 429 утилита ждёт сама.
- Принимаются фото JPEG, PNG, TIFF, WebP, HEIC, AVIF, RAW камер (DNG, CR2, CR3, NEF, ARW, ORF, RAF, RW2,
  PEF), PSD и видео. RAW, PSD и AVIF загружаются `media upload` и `import folder` как обычные фото:
  у них есть миниатюры, их можно обработать `media edit` (без `--format` у RAW и PSD результат — JPEG,
  у AVIF — AVIF; у HEIC и AVIF больше 40 Мпикс — JPEG);
  скачивается исходный файл без изменений. Формат файла словами — в `media list` (`format`, например
  «RAW (Canon CR3)»).
- PSD без сведённого изображения, PSD 16 или 32 бит на канал, PSB и слишком большой для сервера RAW
  хранятся, но миниатюр и обработки у них нет — `status` `failed`, причина в карточке файла; перескажи
  человеку (PSD — пересохранить с «Максимальной совместимостью» или копией в 8 бит).
- Сервер может отклонить файл (дубль, неподдерживаемый формат) — причина в выводе; перескажи человеку.
- Скачивание не перезаписывает файлы в папке: занятое имя получает номер медиа впереди.

## Показать фото человеку

Адреса в карточке относительные и требуют ключ — сам по ним человек картинку не увидит. Скачай миниатюры
и покажи файлы:

```sh
artpush paintings thumbs 101,118,184 --to /tmp/превью     # <номер картины>.jpg, главное фото каждой
artpush media download 184 --all --thumbnail --to /tmp/превью   # все фото одной картины
```

Миниатюры для показа каждый раз скачивай заново, в новую папку (или поверх): ранее скачанные файлы не
переиспользуй — главное фото могло смениться, особенно после «Порядок и главное фото».

Claude Code — прочитай файлы как изображения или собери страницу со встроенными (base64) картинками;
Codex — покажи локальные файлы так, как умеет клиент. Папка временная.

## Порядок и главное фото

```sh
artpush media order 184 12,11,13      # полный новый порядок номеров медиа
artpush media main 184 12
```

Без подтверждения: это обратимо и делается по прямой просьбе.

## Перенос в другую картину — только с подтверждением

```sh
artpush media transfer --ids 12,13 --to 187 --preview --table
artpush media transfer --ids 12,13 --new --catalog 5 --preview --table   # в новую картину
# показать человеку план: какие файлы, откуда, куда; спросить «Перенести? (да / нет)»
artpush media transfer --ids 12,13 --to 187 --apply pv_…
```

- `--apply` — с теми же `--ids` и `--to`/`--new`, что в preview, и только после явного «да».
- Жетон одноразовый, 10 минут; после ошибки — новый `--preview` и новый вопрос.

## Файлы по требованиям

Поручение вида «подготовь файлы к заявке, вот приглашение». Обработка создаёт новые файлы рядом с
исходными; исходные не меняются.

1. Прочитай текст приглашения целиком.
2. Выпиши требования таблицей: формат, размер (px или см), dpi, объём, цветовой профиль, имя файла.
   Неясное или противоречивое не додумывай — спроси человека.
3. Сопоставь требования с флагами `media edit`:

   | Требование | Флаг |
   |---|---|
   | JPEG / PNG / TIFF / WebP | `--format jpeg` / `--format png` / `--format tiff` / `--format webp` |
   | AVIF / HEIC | `--format avif` / `--format heic` (не больше 40 Мпикс — иначе уменьши размер или JPEG) |
   | PDF | `--format pdf` (изображение внутри — JPEG) |
   | PDF без сжатия / без потерь | `--format pdf --pdf-image lossless` |
   | TIFF без сжатия | `--format tiff --tiff-compression none` (по умолчанию LZW; `zip` — ZIP) |
   | «просто перевести в JPEG», объём не задан | `--format jpeg` без `--max-mb` |
   | формат не назван | без `--format`: формат исходного (RAW, PSD, HEIC и AVIF больше 40 Мпикс — JPEG) |
   | длинная сторона 2000 px | `--long-side 2000` |
   | ровно 1920×1080 px | `--size-px 1920x1080` (`--fit pad` — поля, `--fit crop` — обрезать) |
   | 30×40 см, 300 dpi | `--size-cm 30x40 --dpi 300` |
   | не больше 2 МБ | `--max-mb 2` (1 МБ = 1024×1024 байт, как в браузере) |
   | качество | `--quality 85` (jpeg, webp, avif, heic, pdf с JPEG; без флага — как у исходного) |
   | Adobe RGB / для печати | `--profile print` (печать RGB, ClayRGB — см. ниже) |
   | для экрана, sRGB | `--profile screen` (по умолчанию) |
   | CMYK | `--profile cmyk` — только jpeg, tiff, pdf |
   | имя «Фамилия_Название» | `--name "Петрова_{name}"` (`{name}` — имя исходного без расширения) |

   - **CMYK** — только если CMYK прямо назван в требованиях. «Для печати» без слова CMYK — это
     `--profile print`; сомневаешься — спроси человека. Скажи ему, что цвета CMYK на экране
     приблизительные, а профиль (ISO Coated v2) стоит уточнить у типографии.
   - **Adobe RGB:** `--profile print` встраивает ClayRGB — по охвату он совместим с Adobe RGB (1998),
     но называется иначе. Если площадка требует файл именно с профилем «Adobe RGB (1998)» по имени,
     скажи это человеку до сохранения: такого профиля система не встраивает.
   - Без `--max-mb` объём не ограничен и проба сжатия не нужна: файл сохраняется сразу с заданным
     качеством. У PNG, TIFF и PDF без потерь объём зависит только от размера: `--max-mb` их не сожмёт,
     проба только измерит — уменьши размер или выбери формат со сжатием.
   - Неподходящие сочетания с явным `--format` утилита отклоняет до запросов (код 1, `usage`):
     `--tiff-compression` не с tiff, `--pdf-image` не с pdf, `--profile cmyk` с png, webp, avif, heic,
     `--quality` у формата без потерь. Без `--format` формат — у исходного каждого файла: файл, к
     формату которого флаг не подходит, не делается (`failed` с причиной), остальные идут.
   - В отчёте (`plan[]`) у каждого файла: `encode`, `profile` (профиль результата), `soft_proof`,
     у TIFF — `tiff_compression`, у PDF — `pdf_image`. При `soft_proof` в `warnings` — «Цвета CMYK на
     экране приблизительные; профиль уточните у типографии»: перескажи человеку.

4. Найди номера файлов (`artpush media list 184 --table`) и получи отчёт без сохранения:

   ```sh
   artpush media edit 31,45 --format jpeg --long-side 2000 --max-mb 2 --name "{name}-заявка" --label Выставка --dry-run
   artpush media edit 31 --format tiff --tiff-compression none --size-cm 30x40 --dpi 300 --profile cmyk --dry-run
   artpush media edit 31 --format pdf --pdf-image lossless --dry-run
   ```

   В stderr — строки «файл — картина — итог px/см/dpi — формат/качество — объём → имя — предупреждения»,
   в JSON — `plan`. При `--max-mb` объём точный (проба сжатия), иначе — оценка «≈». Ключу только для
   чтения проба недоступна: объём будет оценкой, об этом скажет предупреждение.
5. Покажи человеку перечень «картина — файл — итоговые параметры — имя» и отметь, что не выполняется.
   Спроси «Сохранить? (да / нет)».
6. Только после явного «да» повтори ту же команду без `--dry-run`, с `--yes` и `--to` — забрать результаты:

   ```sh
   artpush media edit 31,45 --format jpeg --long-side 2000 --max-mb 2 --name "{name}-заявка" --label Выставка --yes --to ~/Заявка
   ```

- `--replace` (заменить содержимое, прежнее станет версией) — только по прямому поручению человека.
- Увеличение сверх исходного (`upscale_needed`) и объём больше предела (`unmet`) утилита не пропустит без
  флага: в `plan[].blocked` сказано, какого. Если хоть один файл требует решения, ничего не делается ни с
  одним файлом (код 3, «Ничего не изменено») — реши с человеком или убери этот файл из списка. Покажи человеку отчёт с предупреждением. Только если он
  согласился, повтори с `--allow-upscale` или `--accept-unmet` и передай его ответ в stdin:
  `echo да | artpush media edit 31 --max-mb 1 --accept-unmet --yes`. `--yes` эти два случая не снимает.
  Никогда не подставляй «да» сам — только дословный ответ человека.
- Итог — `done` и `failed` с причиной; сбой одного файла не останавливает остальные. Перескажи человеку
  `summary`.
- `thumbs_pending` в причине: миниатюры ещё готовятся — повтори через минуту.
- `timeout`: задание продолжает идти на сервере. Не повторяй вслепую — сначала проверь файлы картины
  (`artpush media list 184 --table`), а после `--replace` — версии (`artpush media versions 31 --table`):
  если результат уже есть, повтор создаст второй файл или вторую замену.

## Выравнивание, тон, поля, сведения

Это тоже `media edit`: результат — новый файл (или `--replace` по поручению), план показывается до
сохранения, как в «Файлах по требованиям». Флаги сочетаются с флагами формата и размера.

**Снимок картины под углом** (видна стена, картина — трапеция):

1. Найди углы — ничего не сохраняется:

   ```sh
   artpush media edit 31 --perspective auto
   ```

   Код 3 и «Ничего не изменено: покажите человеку эскиз углов и передайте их числами». В stderr и в
   `corners[]` — `perspective` (углы ВЛ, ВП, НП, НЛ одной строкой, готовой для флага), `found` и
   `sketch` — путь к эскизу (`~/.cache/artpush/edit-31-corners.jpg`).
2. Покажи эскиз человеку (как миниатюры — см. «Показать фото человеку») и спроси: «Углы стоят по углам
   картины? (да / нет)». `found: false` — углы не найдены и стоят по краям снимка: так и скажи.
3. Только после его «да» — тот же вызов с числами из `perspective`:

   ```sh
   artpush media edit 31 --perspective 0.1,0.12,0.9,0.1,0.88,0.9,0.12,0.92 --dry-run
   ```

   Повторите те же `--rotate`/`--flip`, что при `--perspective auto`: углы — в долях снимка после
   поворота и отражения, без них они лягут не туда. Без «да» углы не применяй. Если углы не там — не подбирай числа сам: предложи человеку поправить
   маркеры в редакторе в браузере (карточка файла → «Обработать» → «Выровнять»).
- Пропорция результата — из размеров карточки (`--ratio card`, по умолчанию, если они есть), иначе по
  углам (`--ratio corners`). Углы — для одного файла за вызов: у каждого снимка свои.
- Снимок прямо, но с завалом — `--tilt 2.4` (градусы, плюс — по часовой, от −15 до 15). `--tilt` и
  `--perspective` вместе не применяются.
- В плане выравнивание словами — `plan[].straighten` (и первая строка `notes`): «выровнено по углам,
  пропорция из карточки 3 : 4», «наклон −2,4°». Перескажи человеку.

**Тон и цвет** — числами от −100 до 100 (`--sharpness` — от 0 до 100), умеренно: ±10…30 по словам
человека.

| Просьба | Флаги |
|---|---|
| «убери желтизну», «цвет как в жизни» | `--white-balance auto` (температура и оттенок — в плане, строка «тон»); только с `--dry-run` и показом плана человеку |
| «светлее» / «темнее» | `--brightness 15` / `--brightness -15` |
| «контрастнее», «ярче цвета» | `--contrast 15`, `--saturation 15` |
| «теплее» / «холоднее» | `--temperature 15` / `--temperature -15` |
| «чётче» | `--sharpness 30` |

`--white-balance auto` считает серый по всему кадру: у тёплой картины (охра, закат, золото) он
примет её цвет за желтизну и остудит её. Покажи человеку план с `--dry-run` (температура и оттенок) и
миниатюру, предупреди об этом и сохраняй только после его согласия.

**Поля и подпись** — `%` от короткой стороны картины; цвет — `white`, `black` или `#rrggbb`
(`--border-color`):

| Просьба | Флаги |
|---|---|
| «квадратный файл для Instagram» | `--border-ratio 1:1` (4:5 — `--border-ratio 4:5`; `--border-extra 3` — ещё отступ вокруг) |
| «поля для каталога» | `--border 6` |
| разные поля по сторонам | `--border-sides 4,4,10,4` (сверху, справа, снизу, слева) |
| подпись под картиной | `--caption "{автор}. {название}, {год}"` (`--caption-place left`, `--caption-size 3`, `--caption-color black`) |

- `--border`, `--border-sides` и `--border-ratio` взаимоисключают друг друга.
- Подпись — только если человек её попросил; без `--caption` подписи нет. Поля карточки в шаблоне:
  `{автор}`, `{название}`, `{год}`, `{техника}`, `{материал}`, `{размер}`. Итог подписи — в плане
  (`caption`); пустой — подписи не будет.
- Поля при размере «как есть» увеличивают файл: в плане `framed_from` и строка «поля увеличили размер».

**Сведения в файле** (автор, права, название, описание, ключевые слова) по умолчанию берутся из
карточки на языке человека (`primary_language` из `artpush whoami`).

```sh
artpush media edit 31 --meta-lang en --dry-run                       # название по-английски в файле
artpush media edit 31 --meta-title "Sea buckthorn" --meta-description "" --dry-run
```

- `--meta-title`, `--meta-description`, `--meta-keywords`, `--meta-author`, `--meta-rights`,
  `--meta-url`, `--meta-created` — свой текст; `""` — не записывать; без флага — из карточки. Карточку
  они не меняют.
- `--keep-camera` (прежний `--keep-exif`) — перенести камеру и настройки съёмки; он переносит и дату
  съёмки, если не указан `--keep-date`/`--no-keep-date`. `--keep-date` — дату съёмки (и без камеры),
  `--no-keep-date` — камеру без даты. GPS не переносится никогда.
- Правка одних сведений без прочих флагов сохраняет JPEG и WebP без пересжатия: в плане `passthrough` и
  пометка «без пересжатия». Что окажется в файле — `metadata` в плане; перескажи человеку.

## Карточка файла: метки, заметка, имя, версии

```sh
artpush media label 31 --add Выставка        # --remove Выставка — убрать
artpush media note 31 "Отправлено в галерею"  # пустая строка — убрать заметку
artpush media rename 31 Закат-2026           # расширение остаётся прежним
artpush media versions 31 --table           # прежние версии после замен
artpush media restore 31 5 --yes            # вернуть версию 5 — только после «да» человека
```

`media restore` с `--yes` — только после явного «да» человека на вопрос «Вернуть версию 5?». Никогда не
подставляй «да» сам — только дословный ответ человека.

Метки и заметки видны только в архиве и в выдаваемые файлы не попадают. Окончательно удалить версию
агент не может — предложи человеку сделать это в браузере (карточка файла → «Версии»).

## Ошибки

- `preview_required` (код 2): вызвал перенос без `--preview`/`--apply` — начни с `--preview`.
- Код 2 с `conflict`: картину изменили параллельно — покажи человеку и спроси.
- Код 3: ключ только для чтения или чужая картина — остановись и скажи человеку.
- Код 3 и «Ничего не изменено» у `media edit` / `media restore`: человек не подтвердил или нужен флаг
  решения — ничего не записано; покажи план и спроси.
