# ArtPush для агента

Набор, с которым ИИ-агент (Claude Code, Codex, OpenCode и другие) работает с архивом картин
[ArtPush](https://artpush.fammix.org) от вашего имени: утилита командной строки `artpush` и скиллы, которые
учат агента ею пользоваться. Всё, что агент делает, видно в истории картин с пометкой «через агента».

Проще всего — скажите своему агенту:

> Установи ArtPush по инструкции https://github.com/ConsMikh/artpush-agent

## Для человека: установка своими руками

Понадобится пять минут и интернет. Ничего, кроме набора ArtPush, команда не меняет.

**1. Откройте терминал.**

- macOS: Finder → Программы → Утилиты → Терминал.
- Windows: Пуск → наберите «PowerShell» → откройте «Windows PowerShell».
- Linux: программа «Терминал» в меню приложений.

**2. Вставьте команду и нажмите Enter.**

macOS и Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/ConsMikh/artpush-agent/main/install.sh | sh
```

Windows:

```powershell
irm https://raw.githubusercontent.com/ConsMikh/artpush-agent/main/install.ps1 | iex
```

Команда сама поставит всё нужное и в конце напишет «Установлено: …». Если она просит открыть терминал
заново — закройте окно и откройте новое.

**3. Привяжите ключ.** Ключ — это пропуск агента в ваш архив.

1. Откройте ArtPush → Настройки → Ключи агента и выпустите ключ (секрет показывается один раз —
   скопируйте его).
2. В терминале выполните `artpush init`.
3. На вопрос об адресе нажмите Enter, затем вставьте ключ и нажмите Enter. Ключ при вводе не виден — это
   нормально.

Готово: утилита ответит, под каким именем вы вошли. Теперь откройте своего агента и попросите, например,
«найди мои акварели без описания».

Никому не пересылайте ключ, в том числе в чат с агентом. Если ключ попал не туда — отзовите его там же,
где выпустили, и выпустите новый.

## Если вы ИИ-агент

Выполняй по шагам. Человек может не разбираться в терминале — команды запускай сам, объясняй простыми
словами.

1. **Определи ОС** человека.
2. **Выполни команду установки сам** (ключ не нужен). Если клиент модели блокирует установщик
   (например, защита Claude Code в автоматическом режиме не пускает `curl … | sh` или `irm … | iex`) —
   не обходи блокировку: покажи человеку команду и попроси выполнить её в своём окне терминала, затем
   продолжи с шага 3:
   - macOS и Linux:
     ```sh
     curl -fsSL https://raw.githubusercontent.com/ConsMikh/artpush-agent/main/install.sh | sh
     ```
   - Windows (так код выхода дойдёт до тебя; команда — для bash и PowerShell, не для cmd.exe; человек у
     себя вводит `irm … | iex` без обёртки):
     ```sh
     powershell -NoProfile -Command 'irm https://raw.githubusercontent.com/ConsMikh/artpush-agent/main/install.ps1 | iex; exit $LASTEXITCODE'
     ```
3. **Покажи человеку итог** установки (последние строки вывода). Код выхода не 0 — перескажи строку
   `artpush: …` и что она советует; не обходи ошибку сам. Если установщик просит открыть терминал заново, а
   `artpush` не находится — попроси человека перезапустить тебя в новом окне терминала.
4. **Попроси человека выпустить ключ**: ArtPush → Настройки → Ключи агента. Предел «чтение» — только
   смотреть, «правка» — менять архив.
5. **Попроси человека выполнить `artpush init` в своём окне терминала**, а не через тебя: открыть его
   (macOS: Программы → Утилиты → Терминал; Windows: Пуск → «PowerShell»), выполнить `artpush init` и
   сказать тебе, когда закончит. Утилита спросит адрес (Enter — `https://artpush.fammix.org`) и ключ
   скрытым вводом — ему нужно настоящее окно терминала, поэтому сам `artpush init` не запускай.
   **Ключ в чат не принимай** и не передавай его в аргументах команд. Если человек всё же прислал ключ —
   не повторяй его и предложи отозвать и выпустить новый.
6. **Проверь связь**: `artpush whoami --table` — имя, роль, предел ключа. Код 1 с сообщением про
   настройки — ключ не привязан (вернись к шагу 5); код 3 — ключ отозван, просрочен или мал предел.
7. Если скиллы ArtPush в этом сеансе не видны — попроси человека открыть тебя заново: агенты читают скиллы
   при запуске. Дальше работай по скиллу `artpush`.

## Что ставится и куда

- [`uv`](https://docs.astral.sh/uv/), если его нет (системный Python не нужен и не затрагивается);
- утилита `artpush` (`uv tool install`; на macOS и Linux — `~/.local/bin/artpush`) той версии, что в
  последнем выпуске зеркала;
- скиллы — в общий каталог `~/.local/share/artpush/skills/` (Windows — `%LOCALAPPDATA%\artpush\skills\`), а из
  него в каталоги агентов: на macOS и Linux ссылками, на Windows копиями с файлом-меткой `.artpush-kit`.

Повторный запуск обновляет установку без дублей. Каталог скилла с тем же именем, который поставил не
набор (не ссылка в общий каталог, без метки), установщик не трогает и предупреждает о нём.

Параметры установщика (обычно не нужны):

| macOS и Linux (`… \| sh -s -- ФЛАГ`) | Windows (переменная до команды) | Что делает |
|---|---|---|
| `--version X.Y.Z` | `$env:ARTPUSH_VERSION = "X.Y.Z"` | выпуск вместо последнего |
| `--from ПАПКА` | `$env:ARTPUSH_FROM = "ПАПКА"` | папка с `artpush_cli-*.whl` и `skills/` вместо скачивания |
| `--no-skills` | `$env:ARTPUSH_NO_SKILLS = "1"` | только утилита |

На macOS и Linux вместо `--version` можно задать переменную `ARTPUSH_VERSION`. На Windows переменная
`$env:…` действует до закрытия окна PowerShell: введите её и команду установки в одном окне.

### Где агенты ищут скиллы

| Агент | Каталог | Как подключено |
|---|---|---|
| Claude Code | `~/.claude/skills/<имя>/SKILL.md` | установщик |
| Codex | `~/.agents/skills/<имя>/SKILL.md` (уровень пользователя, документация Codex «Build skills», developers.openai.com/codex/skills) | установщик |
| OpenCode | отдельного каталога нет: OpenCode сам читает `~/.claude/skills` и `~/.agents/skills` (opencode.ai/docs/skills, проверено 22.10.2026) | ничего делать не нужно |
| другие агенты со стандартом Agent Skills (Gemini CLI, Hermes…) | свой каталог скиллов агента | подключите `~/.local/share/artpush/skills/` или сделайте ссылки на его подкаталоги |
| агент без скиллов | — | `artpush --help` и этот README |

На Windows `~` — это папка профиля `%USERPROFILE%`.

## Обновление

```sh
artpush update
```

Ставит из зеркала выпуск той же версии, что у системы ArtPush (утилиту и скиллы); ключ и настройки
остаются. Нужен после выпуска новой версии ArtPush, когда утилита предупреждает «набор …, система … —
выполните artpush update» и когда она сообщает о несовпадении контракта (код выхода 5).

- macOS и Linux: обновление идёт в том же окне.
- Windows: открывается отдельное окно установки, а команда сразу отвечает `{"updated": "started", …}`.
  Дождитесь в том окне «Готово», нажмите Enter и откройте агента заново.

Если выпуска нужной версии в зеркале нет, `artpush update` так и скажет (код 1) — установленный набор
остаётся рабочим; это вопрос к администратору ArtPush.

## Настройка

```sh
artpush init          # спросит адрес (по умолчанию https://artpush.fammix.org) и ключ скрытым вводом
artpush init --url https://…   # другая система, например стенд
artpush whoami        # кто я, роль, предел ключа
```

Порядок поиска настроек: флаги `--url`/`--key` → переменные `ARTPUSH_URL`/`ARTPUSH_TOKEN` → файл
`~/.config/artpush/credentials` (другой путь — `ARTPUSH_CONFIG`). Флаг `--key` виден в списке процессов,
поэтому лучше `artpush init`.

Ключ имеет предел: `read` (только чтение), `write` (чтение и правка), `admin` (плюс администрирование, только
у администратора) — и срок 7, 30 или 90 дней. Отозвать ключ можно там же, где его выпустили.

## Команды

Вывод — JSON в stdout (его читает агент), сообщения — в stderr; `--table` — таблица для человека.
Справка: `artpush --help`, `artpush <команда> --help`.

| Группа | Команды |
|---|---|
| служебные | `init`, `whoami`, `contract`, `update` |
| поиск и карточка | `paintings search`, `painting get / create / set / text / price / delete / derive` |
| массовое заполнение | `bulk preview`, `bulk apply`, `bulk undo` |
| медиа | `media upload / download / list / order / main / transfer` |
| обработка и карточка файла | `media edit` (формат, размер, объём — новые файлы или `--replace`), `media label / note / rename / versions / restore` (окончательного удаления версий нет — только в браузере) |
| каталоги | `catalogs tree`, `catalog add / members / delete` |
| заметки и история | `notes list / add`, `history`, `events add` |
| корзина | `trash list / restore` (очистки нет — только в браузере) |
| импорт | `import folder / review / regroup / rename / skip / create / sessions / discard` |
| Artnow | `artnow check / start / resume / wait / stop / works / create` |
| администрирование | `admin dicts / journal / integrity / keys / users` |
| прочее | `call <METHOD> <путь>` — сырой вызов операции из контракта |

## Подтверждение человеком

Утилита не решает за человека. Массовые и необратимые действия идут в два шага: `--preview` печатает,
что изменится, и жетон; `--apply <жетон>` применяет. Жетон живёт 10 минут, одноразовый и привязан к
выборке — применить, не получив предпросмотр, нельзя. Скиллы требуют от агента показать предпросмотр
человеку и дождаться явного «да». Удаление картины в корзину — `painting delete <id> --yes`; без `--yes`
команда только показывает, что будет удалено.

## Коды выхода

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | прочая ошибка (сеть, неверные аргументы, значение не найдено) |
| 2 | конфликт версии (картину изменили после того, как агент её читал; утилита помнит виденные версии сутки в `~/.cache/artpush/versions.json`; записать поверх — `--overwrite`) или нужен предпросмотр |
| 3 | нет прав: предел ключа мал, ключ отключён, просрочен или отозван |
| 4 | превышен темп (утилита уже ждала и повторяла сама) |
| 5 | контракт системы не совпадает с утилитой — `artpush update` (так отказывают изменяющие команды; команды чтения выполняются с предупреждением в stderr) |

Темп по ключу: 120 запросов и 60 загрузок файлов в минуту.
